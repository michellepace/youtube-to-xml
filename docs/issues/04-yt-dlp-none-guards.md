# Remove (or prove) the None guards on yt-dlp results that need type: ignore

## Problem

Two checks guard against yt-dlp returning `None`. Both silence pyright with `# type: ignore`, and both came with the comment "Stubs say non-None, but yt-dlp can return None at runtime":

https://github.com/michellepace/youtube-to-xml/blob/31a8828f2bcea8290fa8bd67c768b42ce4f27d42/src/youtube_to_xml/url_parser.py#L186-L188
https://github.com/michellepace/youtube-to-xml/blob/31a8828f2bcea8290fa8bd67c768b42ce4f27d42/src/youtube_to_xml/url_parser.py#L263-L266

The second one raises "Something weird happened…", which suggests nobody has seen it happen.

In yt-dlp 2026.10.21, `extract_info` returns `None` only through `_handle_extraction_exceptions` when `ignoreerrors` is set. Without it, `report_error` raises a `DownloadError`, which the code already maps. We never set `ignoreerrors`, so both branches look unreachable. They are untested, and they hide the type checker's warning about that.

The comment was removed in the comment audit (ADR 0001), and this issue tracks the workaround it justified.

## Suggested fix

Either:
- confirm the branches are unreachable with our options, then delete both guards and their `type: ignore`s, or
- find a real input that returns `None`, add a slow test for it, and keep the guard with a specific error message.

While there, the `# type: ignore[reportArgumentType]` on `yt_dlp.YoutubeDL(yt_dlp_options)` could probably go if `yt_dlp_options` is typed as yt-dlp's params type.
