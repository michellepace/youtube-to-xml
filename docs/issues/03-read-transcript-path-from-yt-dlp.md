# Read the transcript file path from yt-dlp instead of rebuilding it from its naming scheme

## Problem

`url_parser` guesses where yt-dlp wrote the subtitle file by copying yt-dlp's file-naming scheme. A comment existed only to explain that guess (`yt-dlp appends ".<lang>.json3"`):

https://github.com/michellepace/youtube-to-xml/blob/31a8828f2bcea8290fa8bd67c768b42ce4f27d42/src/youtube_to_xml/url_parser.py#L78-L79
https://github.com/michellepace/youtube-to-xml/blob/31a8828f2bcea8290fa8bd67c768b42ce4f27d42/src/youtube_to_xml/url_parser.py#L267-L269

If yt-dlp changes how it names files, or sanitises the language code differently, the file is "not found" and the user sees `URLTranscriptNotFoundError`, which is the wrong error.

The comment was removed in the comment audit (ADR 0001), and this issue tracks the workaround it described.

## Suggested fix

yt-dlp records the real path. After `process_ie_result(..., download=True)` it sets `info["requested_subtitles"][lang]["filepath"]` (see `YoutubeDL._write_subtitles`). Read the path from there and drop the `_TRANSCRIPT_FILE_STEM` + `.{lang}.json3` reconstruction. `outtmpl` can stay as it is.
