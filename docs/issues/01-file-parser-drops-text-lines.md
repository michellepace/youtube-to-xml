# File parser silently drops transcript text lines after the first one

## Problem

`_convert_strings_to_transcript_lines` in `file_parser.py` assumes each timestamp is followed by exactly one text line. When it finds a non-timestamp line that has no timestamp before it, it skips the line without saying so:

https://github.com/michellepace/youtube-to-xml/blob/31a8828f2bcea8290fa8bd67c768b42ce4f27d42/src/youtube_to_xml/file_parser.py#L235-L258

The comments there, "shouldn't happen normally" and "shouldn't happen / Skip it", excused this branch. They were removed in the comment audit (ADR 0001, `docs/adr/0001-ban-code-comments.md`), and this issue tracks the behaviour they were hiding.

It does happen. Any gap of 3 or more lines between timestamps is not a chapter boundary (ADR 0002), so the extra text lines reach this branch and are lost:

```python
>>> parse_transcript_file("Intro\n0:00\nContent\n2:30\nLine 1\nLine 2\nLine 3\n7:30\nMore content")
# chapter "Intro" lines: [(0.0, 'Content'), (150.0, 'Line 1'), (450.0, 'More content')]
# "Line 2" and "Line 3" are gone, with no error or warning
```

`test_no_chapter_when_three_line_gap` uses exactly this input but only asserts the chapter count, so it misses the data loss.

## Suggested fix

1. Add a test asserting what should happen to `Line 2` and `Line 3`. Either they are joined onto the previous timestamp's text (most likely what the user wants), or the file is rejected with `FileInvalidFormatError`.
2. Make `_convert_strings_to_transcript_lines` follow that contract, and remove the "can't happen" branches.
3. Decide whether two timestamps in a row (currently each gets empty text) is valid input, and cover it with a test.
