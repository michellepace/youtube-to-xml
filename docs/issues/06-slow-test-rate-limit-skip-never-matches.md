# Slow tests' rate-limit skip never matches, so YouTube throttling fails the suite

## Problem

The slow tests' `run_cli` helpers are meant to skip when YouTube rate-limits or bot-checks the run. The comment said "Handle rate limiting - skip test if encountered":

https://github.com/michellepace/youtube-to-xml/blob/31a8828f2bcea8290fa8bd67c768b42ce4f27d42/tests/test_end_to_end.py#L61-L65
https://github.com/michellepace/youtube-to-xml/blob/31a8828f2bcea8290fa8bd67c768b42ce4f27d42/tests/test_exceptions_url.py#L30-L34

The helpers look for `"429"`, `"rate limit"` or `"bot protection"` in the CLI's output. Since exception messages were centralised, the CLI prints the mapped messages, and none of them contain those words:

- `URLRateLimitError`: "YouTube is temporarily limiting requests - try again later"
- `URLBotProtectionError`: "YouTube requires verification - try switching networks"

So the comment had gone stale. When YouTube throttles a run, the tests fail instead of skipping.

The comment was removed in the comment audit (ADR 0001). The decision to skip on throttling is recorded in ADR 0006.

## Suggested fix

Match on the real messages, `EXCEPTION_MESSAGES["url_rate_limit_error"]` and `EXCEPTION_MESSAGES["url_bot_protection_error"]`, so the skip cannot drift again. Better still, move the three copies of `run_cli` (`test_cli.py`, `test_end_to_end.py`, `test_exceptions_url.py`) into one `tests/conftest.py` helper.

`test_bot_protection_handles_gracefully` should then stop accepting either outcome and test something definite.
