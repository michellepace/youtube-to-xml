# "Development" console log handler shows users a full traceback on system errors

## Problem

`setup_logging()` adds a stderr handler at `ERROR` level, introduced by the comment "Also ensure console output for errors during development":

https://github.com/michellepace/youtube-to-xml/blob/31a8828f2bcea8290fa8bd67c768b42ce4f27d42/src/youtube_to_xml/logging_config.py#L33-L41

Nothing limits it to development, so it runs for every user. When the CLI hits an `OSError` it already prints a friendly `❌` message, and then `logger.exception(...)` sends the whole traceback to the terminal through this handler:

```text
$ mkdir in.xml && youtube-to-xml in.txt
❌ [Errno 21] Is a directory: 'in.xml'

Try: youtube-to-xml --help
ERROR - [aef9d629] System error
Traceback (most recent call last):
  File ".../cli.py", line 179, in main
  ...
IsADirectoryError: [Errno 21] Is a directory: 'in.xml'
```

The comment was removed in the comment audit (ADR 0001), and this issue tracks the behaviour behind it.

Two related problems:
- `setup_logging()` writes `youtube_to_xml.log` into whatever directory the user runs the command from.
- Calling `setup_logging()` twice adds a second console handler.

## Suggested fix

Remove the console handler, or turn it on only with a flag such as `--verbose` or an environment variable. The file log already records the traceback. Add a CLI test asserting that stderr contains no `Traceback` when an `OSError` occurs.
